# 政府智慧會議紀錄生成系統

把會議錄音變成「符合公文格式、有憑有據」的會議紀錄——選好會議類型、上傳錄音檔，就能下載 Word 或 Markdown 格式的紀錄。

[![Version](https://img.shields.io/badge/version-4.8.1-green)](CHANGELOG.md)
[![Platform](https://img.shields.io/badge/platform-macOS%20|%20Windows%20|%20Linux-informational)](doc/操作手冊/)
[![Stability](https://img.shields.io/badge/stability-stable-brightgreen)](CHANGELOG.md)

## 😣 想解決的痛點

- **整理會議紀錄很花時間**：聽錄音、抓重點、繕打，一場會常常要花上好幾個小時。
- **格式常與公文規範有落差**：每個人寫法不一樣，格式調整與來回修改很費工。
- **擔心 AI 亂編**：一般 AI 工具可能寫出「會議中沒講到的決議」，甚至自行填入人名或單位。
- **機敏會議不能上傳雲端**：採購評選等機敏會議的資料依法不得傳到外部服務，一般雲端 AI 無法使用。

## 🎯 這個系統做什麼

上傳會議錄音 → 自動產生逐字稿 → 依會議類型套用對應的公文格式 → 產生會議紀錄（Word／Markdown）。

三個保證：

- **忠於逐字稿**：只根據錄音內容撰寫；查不到的資訊會標註「（待確認）」，不會自行編造。
- **可全程離線**：本地模式不需要網路，音檔與內容都留在自己的電腦。
- **格式可擴充**：各種會議類型有專屬格式，未來可持續新增。

## ✨ 主要功能

- **4 種會議類型**：一般會議（預設）、科務會議、採購評選會（僅限本地模式）、ISMS月工作會議。
- **雙格式下載**：Markdown（.md）與 Word（.docx）；部分類型另附附件（如科務會議的列管資料）。
- **逐字稿可另外下載**：方便核對與存檔。
- **多人會議發言者標註**：逐字稿可自動標出「發言者1／2／3…」與時間戳，方便核對誰說了什麼（標籤是系統自動分群編號，不是姓名）。
- **雲端紀錄保留發言來源**：雲端模式的會議紀錄會在句末保留發言來源標註「（發言者1，00:12:04）」，方便回溯是誰說的（標籤是系統自動分群編號，不是姓名）。
- **不亂編年份**：查不到的資訊（包含會議日期）一律標「（待確認）」，系統不會自己推算或編造年份。
- **雲端一次讀完整份逐字稿**：雲端模式一次把整份逐字稿交給 AI 萃取重點（分段方式是給本地模式、記憶體有限的場合使用）。
- **即時進度顯示**：處理到哪一步，畫面都看得到。
- **排隊處理**：任務會排隊依序處理，畫面顯示排隊件數與順位。
- **支援常見音訊格式**：MP3、MP4、WAV、M4A、MKV、WebM、FLAC、OGG、AVI、MOV。

## 💻 系統需求

| 項目 | 需求 |
|---|---|
| macOS | macOS 26 以上（Apple Silicon 機型） |
| Windows | Windows 10／11（建議環境） |
| Linux | Ubuntu 20.04 以上（建議環境） |
| 記憶體 | 16GB 以上（建議值，本地模式） |
| 硬碟空間 | 20GB 以上（建議值，本地模式） |
| 操作方式 | 用瀏覽器開啟即可（Chrome／Edge／Safari 等） |

> 🍎 **Mac 使用者請注意**：Mac 版使用的語音引擎是 macOS 內建的 Apple SpeechAnalyzer，需要 macOS 26 以上＋Apple Silicon，不需另外下載語音模型；符合條件的 Mac 上沒有備援引擎——macOS 26 以下時轉錄會直接失敗，不會偷偷改用別的方法。Intel Mac 不支援此引擎（系統會改走舊方法，屬非正式支援組合），建議改用 Windows／Docker 或 Apple Silicon 機器。
>
> 🪟 **Windows／Linux 不受影響**：使用 Whisper 系列語音模型（第一次使用時下載），行為與過去完全相同；Windows 正式主機不會因為 Mac 的調整而有任何改變。

## 🚀 快速開始

### 機關同仁（最常見）

**不用安裝任何東西**，用瀏覽器打開系統網址就能使用：

- 安裝在自己的電腦：`http://localhost:9527`
- 正式機：請洽系統管理員取得網址

### Windows 電腦（建議使用 Docker）

```bash
cd docker
docker compose -f docker-compose-windows-gpu.yml up -d
```

> 沒有 NVIDIA 顯示卡的話，改用標準版：`cd docker && docker compose up -d`
>
> 第一次執行 `up -d` 時 Docker 會自動建置映像（第一次會比較久）；之後日常更新先 `git pull` 抓最新程式，再用 `restart` 重新啟動，只有套件清單或 Dockerfile 有變更才需要重建（請勿加上 `--no-cache`）。

### macOS（安裝在自己的電腦）

需要先安裝 `uv` 與 `ffmpeg`（缺少會無法啟動）：

```bash
uv sync --frozen
./start_service.sh
```

Mac 需要先「一次性」建置一個小工具，用來呼叫 macOS 內建的語音引擎（之後都不用再建置）：

```bash
cd apple_speech_cli && swift build -c release
```

### 選擇 AI 處理模式

- **雲端模式**（需要網路）：先複製設定檔並填入雲端 provider 的金鑰
  （預設使用 Gemini，需 `GEMINI_API_KEY`；也可切換 Ollama Cloud，改填 `OLLAMA_API_KEY`）：
  ```bash
  cp .env.example .env
  # 編輯 .env，填入 GEMINI_API_KEY（改用 Ollama Cloud 時改填 OLLAMA_API_KEY）
  ```
- **本地模式**（完全離線）：
  - **Windows／Docker**：安裝 Ollama 後執行 `ollama pull gemma4:31b`。
  - **macOS**：預設搭配 LM Studio（開啟 LM Studio 的本地伺服器功能）。

> 更完整的安裝、更新與維護步驟，請見[使用者手冊](doc/操作手冊/使用者手冊.md)與[部署更新手冊](doc/操作手冊/部署更新手冊_v4.1.md)。

## 📖 使用方式

1. **選擇會議類型**（一般會議／科務會議／採購評選會／ISMS月工作會議）。
2. **選擇處理模式**（本地或雲端；機敏類型會自動鎖定為本地模式）。
3. **上傳會議錄音檔**（單檔上傳，任務會排隊處理）。
4. **下載會議紀錄**（Word／Markdown；需要時可加下逐字稿）。

## 🔒 隱私與資料安全

- **本地模式 100% 離線**：音檔、逐字稿與會議紀錄都留在自己的電腦，不會上傳到雲端。
- **機敏會議強制本地**：採購評選會等機敏類型會鎖定本地模式（前端鎖定＋後端檢查雙重防護），無法誤用雲端。
- **過期檔案自動清理**：超過保留期限的檔案會自動刪除。

## ❓ 常見問題

**一定要連網嗎？**
不一定。本地模式可全程離線；雲端模式才需要網路，以及雲端 provider 的金鑰（預設使用 Gemini，需 `GEMINI_API_KEY`；也可切換 Ollama Cloud，改填 `OLLAMA_API_KEY`）。Mac 第一次使用內建語音引擎時，系統可能需要先連線下載一次語音資源（僅此一次，之後即可離線使用）。

**Mac 為什麼要先建置一個小工具？**
Mac 版使用 macOS 內建的 Apple 語音引擎，需要一個小工具負責呼叫。這是「一次性」步驟，完成後就不用再處理。

**選錯會議類型怎麼辦？**
在結果頁按「重新開始」，重新上傳同一份錄音並選擇正確的會議類型即可重新產生。

**紀錄會不會自己編造內容？**
不會。系統只依逐字稿產生紀錄；查不到的資訊會標註「（待確認）」，不會自行填入人名、單位或決議。

**支援哪些錄音格式？**
MP3、MP4、WAV、M4A、MKV、WebM、FLAC、OGG、AVI、MOV。
