## 2. 第一性原理分析

### 2.1 問題根源識別

#### A. Whisper 逐字稿層問題
- **問題**：`initial_prompt` 被錯誤地包含在輸出中
- **證據**：逐字稿開頭出現「請使用正體中文的會議逐字稿，請使用正體中文輸出...」重複多次
- **影響**：污染輸入，導致 LLM 理解受阻
- **修復**：修改 `initial_prompt` 為範例格式而非指令格式

#### B. 地端 LLM 指令遵循能力差異
- **問題**：Gemma 3 27B 對 XML 標籤格式的解析能力較弱
- **證據**：未能遵循 `<output_format>` 中指定的章節結構
- **影響**：輸出缺乏待辦事項表格、會議概況等必要區塊

#### C. 參數配置不足
- **問題**：原配置僅設定 `temperature: 0.1`
- **影響**：缺乏 `num_ctx`、`repeat_penalty` 等關鍵參數
- **結果**：長逐字稿可能被截斷，輸出易重複

## 3. 改善方案實作

### 3.1 Whisper 轉錄層優化

```python
# 修改前（問題代碼）
traditional_chinese_prompt = "以下是台灣繁體中文的會議逐字稿，請使用正體中文輸出。"

# 修改後（最佳實踐）
traditional_chinese_prompt = "這是一場專業會議的逐字記錄，討論主題包含專案進度、決議事項。"
```

**改善原理**：
- Whisper 的 `initial_prompt` 應該是「範例內容」而非「指令」
- 使用範例內容格式，可引導模型輸出類似風格，而不會被混入輸出中

### 3.2 System Prompt 重構

**改善前**：使用 XML 標籤結構（COSTAR-X 框架）
- `<system_instruction>`, `<role>`, `<instructions>` 等
- 對雲端 API 友善，但地端模型解析較差

**改善後**：使用純 Markdown 結構
- 步驟化工作流程說明
- 明確的輸出格式範例
- 直接的規則列表

**關鍵改變**：
1. 移除 XML 標籤，改用 Markdown 標題
2. 添加「直接輸出」規則，避免 LLM 加入開場白
3. 提供完整的輸出範例模板

### 3.3 Ollama API 參數優化

```python
# 修改前
"options": {
    "temperature": 0.1
}

# 修改後
"options": {
    "temperature": 0.1,       # 低溫提高格式遵循度
    "top_p": 0.9,             # 控制輸出多樣性
    "top_k": 40,              # 限制候選詞數量
    "repeat_penalty": 1.15,   # 防止重複
    "num_ctx": 8192,          # 擴大上下文視窗
    "num_predict": 4096,      # 允許更長輸出
    "stop": ["---\n\n## 原始逐字稿"]  # 停止標記
}
```

### 3.4 輸出後處理機制

新增 `_clean_ollama_output()` 函數：
- 移除 LLM 常見的無用前綴（「好的，我來整理...」）
- 確保輸出以正確的標題開頭
- 使用正則表達式匹配多種變體
