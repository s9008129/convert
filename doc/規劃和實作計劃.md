## CO-STAR-A 框架說明

### 背景

本專案基於論文《COSTAR-A: A Novel Prompt Engineering Framework》進行升級，將原本的 CO-STAR 六元素框架擴展為 CO-STAR-A 七元素框架。

### 框架對比

| 框架 | 元素數量 | 元素 |
|------|----------|------|
| CO-STAR | 6 | Context, Objective, Style, Tone, Audience, Response |
| **CO-STAR-A** | 7 | Context, Objective, Style, Tone, Audience, Response, **Answer** |

### Answer 元素定義

**Answer (回答指引)** 是 CO-STAR-A 新增的第七個元素：

- **回答類型**: 直接回答、分析性、建議性、比較性、教學性
- **必須包含**: 指定回答必須涵蓋的要素
- **必須避免**: 指定回答必須迴避的內容（如自稱 AI）
- **強制回應**: 要求模型必須直接回答，不可迴避

### 論文實驗結果

| 模型 | CO-STAR 決定性 | CO-STAR-A 決定性 | 改善率 |
|------|----------------|------------------|--------|
| Yi-Coder-1.5B | 71.4% | 100% | +40% |
| Llama3.1-8B | 28.6% | 100% | +250% |
| Qwen2.5-3B | 100% | 100% | 0% |

## 第一性原理分析

### 問題本質拆解

從第一性原理思考，我們需要回答以下核心問題：

#### 1. **使用者真正需要什麼？**
```
根本需求 = 想要 AI 產生高品質結果
↓
障礙 = 不知道如何與 AI 溝通
↓
痛點 = 提示詞寫得不夠精確、缺乏結構
↓
解決方案 = 提供結構化的引導，讓使用者「填空」就能產生專業提示詞
```

#### 2. **什麼構成一個「好的提示詞」？**

根據最新研究（Google AI、OpenAI、IBM 提示工程指南），優質提示詞必須具備：

| 元素 | 說明 | 重要性 |
|------|------|--------|
| **明確性** | 清晰無歧義的指令 | ⭐⭐⭐⭐⭐ |
| **上下文** | 背景資訊與情境設定 | ⭐⭐⭐⭐⭐ |
| **角色定義** | AI 應扮演的專家角色 | ⭐⭐⭐⭐ |
| **輸出格式** | 期望的回應結構 | ⭐⭐⭐⭐ |
| **約束條件** | 限制範圍與規則 | ⭐⭐⭐ |
| **範例** | Few-shot 學習樣本 | ⭐⭐⭐ |
| **語調風格** | 回應的口吻與氣質 | ⭐⭐⭐ |

#### 3. **為什麼現有工具不足？**

| 現有方案 | 缺陷 |
|----------|------|
| 直接寫提示詞 | 需要專業知識，學習曲線陡峭 |
| 提示詞模板庫 | 靜態、缺乏個人化、無法動態調整 |
| ChatGPT 直接問 | 結果不穩定、缺乏系統性方法論 |

### 核心假設

1. **假設一**: 結構化參數能顯著提升提示詞品質
2. **假設二**: AI 能有效整合離散參數為連貫的提示詞
3. **假設三**: 視覺化介面能降低使用門檻

### LLM 客戶端實作

```typescript
// lib/llm-client.ts
import OpenAI from 'openai';

// 支援的 Provider 類型
type LLMProvider = 'openai' | 'ollama' | 'lmstudio' | 'custom';

interface LLMConfig {
  provider: LLMProvider;
  baseURL?: string;
  apiKey?: string;
  model: string;
}

// Provider 預設配置
const PROVIDER_CONFIGS: Record<LLMProvider, { baseURL: string; apiKey: string }> = {
  openai: {
    baseURL: 'https://api.openai.com/v1',
    apiKey: process.env.OPENAI_API_KEY || '',
  },
  ollama: {
    baseURL: process.env.LLM_BASE_URL || 'http://localhost:11434/v1',
    apiKey: 'ollama', // Ollama 忽略此值但 OpenAI SDK 需要
  },
  lmstudio: {
    baseURL: process.env.LLM_BASE_URL || 'http://localhost:1234/v1',
    apiKey: 'lm-studio', // LM Studio 忽略此值但 OpenAI SDK 需要
  },
  custom: {
    baseURL: process.env.LLM_BASE_URL || '',
    apiKey: process.env.LLM_API_KEY || 'not-needed',
  },
};

// 建立 LLM 客戶端 (統一使用 OpenAI SDK)
export function createLLMClient(config?: Partial<LLMConfig>): OpenAI {
  const provider = (config?.provider || process.env.LLM_PROVIDER || 'openai') as LLMProvider;
  const providerConfig = PROVIDER_CONFIGS[provider];
  
  return new OpenAI({
    baseURL: config?.baseURL || providerConfig.baseURL,
    apiKey: config?.apiKey || providerConfig.apiKey,
    timeout: provider === 'openai' ? 30000 : 120000,
    maxRetries: 2,
  });
}

// 取得當前配置的模型名稱
export function getDefaultModel(): string {
  const provider = process.env.LLM_PROVIDER || 'openai';
  const defaultModels: Record<string, string> = {
    openai: 'gpt-4o-mini',
    ollama: 'llama3.2',
    lmstudio: 'loaded-model',
    custom: process.env.LLM_MODEL || 'default',
  };
  return process.env.LLM_MODEL || defaultModels[provider];
}

// 匯出預設客戶端實例
export const llmClient = createLLMClient();
export const defaultModel = getDefaultModel();
```

```dockerfile
FROM node:20-alpine AS deps

# ============================================
# Stage 2: Builder
# ============================================

WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

ENV NEXT_TELEMETRY_DISABLED=1
ENV NODE_ENV=production

RUN npm run build

# ============================================
# Stage 3: Runner (Production)
# ============================================
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000

ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

CMD ["node", "server.js"]
```

### 部署腳本

```bash
#!/bin/bash
# deploy.sh

set -e

echo "🚀 PromptCraft Deployment Script"
echo "================================"

MODE=${1:-production}

case $MODE in
  "dev")
    echo "📦 Starting development environment..."
    docker-compose -f docker-compose.dev.yml up --build
    ;;
  "production")
    echo "📦 Building production image..."
    docker-compose build
    
    echo "🔽 Pulling Ollama models..."
    docker-compose up -d ollama
    sleep 10
    docker exec promptcraft-ollama ollama pull llama3.2
    
    echo "🚀 Starting all services..."
    docker-compose up -d
    
    echo "✅ Deployment complete!"
    echo "   App: http://localhost:3000"
    echo "   Ollama: http://localhost:11434"
    ;;
  "cloud")
    echo "☁️ Cloud mode (OpenAI API)..."
    LLM_PROVIDER=openai docker-compose up -d app
    ;;
  "lmstudio")
    echo "🖥️ LM Studio mode (external local LLM)..."
    echo "⚠️  請確保 LM Studio 已啟動並開啟 Local Server (port 1234)"
    
    if curl -s http://localhost:1234/v1/models > /dev/null 2>&1; then
      echo "✅ LM Studio 連線成功"
    else
      echo "❌ 無法連線到 LM Studio"
      exit 1
    fi
    
    LLM_PROVIDER=lmstudio \
    LLM_BASE_URL=http://host.docker.internal:1234/v1 \
    docker-compose up -d app
    
    echo "✅ Deployment complete!"
    ;;
  "status")
    docker-compose ps
    curl -s http://localhost:3000/api/health 2>/dev/null || echo "App not running"
    ;;
  "logs")
    docker-compose logs -f ${2:-app}
    ;;
  "stop")
    docker-compose down
    ;;
  *)
    echo "Usage: ./deploy.sh [dev|production|cloud|lmstudio|status|logs|stop]"
    exit 1
    ;;
esac
```

## 風險評估與緩解策略

### 技術風險

| 風險 | 機率 | 影響 | 緩解策略 |
|------|------|------|----------|
| LLM API 故障 | 低 | 高 | 實作重試機制、Provider 切換 |
| API 配額用盡 | 中 | 高 | 切換到地端 Ollama/LM Studio |
| Docker 容器故障 | 低 | 高 | Health check、自動重啟 |
| 效能瓶頸 | 低 | 中 | 串流回應、地端模型分流 |
| 安全漏洞 | 低 | 高 | 環境變數、輸入驗證、非 root 用戶 |

### 緩解措施：LLM Provider 自動 Fallback

```typescript
async function callLLM(prompt: string): Promise<string> {
  const providers = [
    { provider: 'ollama', model: process.env.LLM_MODEL || 'llama3.2' },
    { provider: 'lmstudio', model: 'loaded-model' },
    { provider: 'openai', model: 'gpt-4o-mini' },
  ];
  
  for (const config of providers) {
    try {
      const client = createLLMClient(config);
      const response = await client.chat.completions.create({
        model: config.model,
        messages: [{ role: 'user', content: prompt }],
      });
      return response.choices[0].message.content || '';
    } catch (error) {
      console.warn(`Provider ${config.provider} failed, trying next...`);
      continue;
    }
  }
  throw new Error('All LLM providers failed');
}
```

### D. 常見問題 (FAQ)

**Q: Ollama 和 LM Studio 有什麼差別？**
| 特點 | Ollama | LM Studio |
|------|--------|-----------|
| 介面 | CLI / API | GUI 桌面應用 |
| Docker 支援 | ✅ 原生支援 | ❌ 需外部連線 |
| 模型格式 | GGUF, Safetensors | GGUF, MLX |
| 適合情境 | 伺服器、自動化 | 本機開發、實驗 |

**Q: Docker 容器無法連線到 LM Studio？**
- 確認 LM Studio Local Server 已啟動
- 使用 `host.docker.internal:1234` 而非 `localhost:1234`
- macOS/Windows 原生支援，Linux 需額外設定
