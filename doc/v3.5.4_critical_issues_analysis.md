## 🔍 第一原理分析

### 問題 1 根本原因：阻塞式 I/O 與資源爭用

**物理層面**：
- GPU 是**有限資源**，同時只能處理有限數量的任務
- Apple M4 Pro MPS：16 個 GPU 核心，100% 使用率時無法接受新任務
- 記憶體使用：30.80 GB / 48.00 GB (64%)，接近臨界值

**系統層面**：
```
客戶端 A（GPU 滿載）          客戶端 B（新連線）              伺服器
     |                              |                           |
     |------ 處理中（佔用 GPU）------|                           |
     |                              |---- HTTP GET / ---------->|
     |                              |                           |
     |                              |                           |--> 等待 GPU 資源
     |                              |                           |--> 阻塞請求
     |                              |                           |--> 無超時限制
     |                              |                           |
     |                              |<----- 無回應 -------------|
     |                              | (瀏覽器一直轉圈圈)         |
```

**程式層面**：
1. **FastAPI/Uvicorn 預設行為**：
   - 每個請求由獨立的協程處理
   - **無預設請求超時限制**
   - 阻塞操作會導致協程掛起，但不會釋放 HTTP 連線

2. **目前架構問題**：
   ```python
   # backend/api/routes.py - health_check()
   @router.get("/health", response_model=HealthStatus)
   async def health_check():
       device_detector.detect_best_device()  # 同步阻塞調用
       # 如果 GPU 滿載，此函數會長時間阻塞
   ```

3. **排隊機制的侷限性**：
   - 現有排隊機制只管理**上傳後的任務**
   - **不管理 HTTP 請求本身**
   - 當 GPU 滿載時，連 `/api/health` 都可能超時

**Context7 MCP 文檔參考**：
根據 Uvicorn 官方文檔：
- Uvicorn **沒有內建的請求超時機制**
- 需要在應用層實作超時控制
- 建議使用 `asyncio.wait_for()` 或中間件實作超時

### 問題 2 根本原因：版本號管理混亂

**發現的版本號位置**：
1. `backend/main.py` 第 23 行：`v2.3.6`（啟動日誌）
2. `backend/main.py` 第 70 行：`version="2.3.6"`（FastAPI 元資料）
3. `backend/api/routes.py` 第 65 行：`version="3.5.0"`（health API）

**根本問題**：
- **版本號硬編碼在多處**
- `--reload` 模式只監控 `.py` 檔案變更，不會重新載入常數
- 必須重啟服務才能更新版本號

**最佳實踐**：
- 版本號應該**只定義一次**（Single Source of Truth）
- 從檔案讀取（如 `VERSION` 檔案或 `__version__.py`）
- 或從 Git tag 自動生成

### 問題 3 根本原因：缺乏服務管理文檔

**現狀**：
- 服務使用 `start_service.sh` 啟動，帶 `--reload` 參數
- 修改程式碼後，`--reload` 會自動重載
- **但用戶不清楚何時需要手動重啟**

**需要重啟的情況**：
1. **環境變數變更**（`.env`, `config.yaml`）
2. **版本號變更**
3. **依賴套件更新**（`requirements.txt`）
4. **靜態檔案變更**（`frontend/` 目錄）

**不需要重啟的情況**：
1. **Python 程式碼變更**（`.py` 檔案）- `--reload` 會自動重載

## ✅ 解決方案（基於第一原理）

### 解決方案 1：實作請求級別超時控制

**設計原則**：
1. **優雅降級**：GPU 滿載時，快速返回狀態而非阻塞
2. **非阻塞設計**：所有 HTTP 請求必須有超時限制
3. **快取機制**：裝置狀態不需要每次都重新偵測

**實作方案 A：Middleware 全域超時（推薦）**
```python
# backend/middleware/timeout.py
import asyncio
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import JSONResponse

class TimeoutMiddleware(BaseHTTPMiddleware):
    def __init__(self, app, timeout: float = 30.0):
        super().__init__(app)
        self.timeout = timeout
    
    async def dispatch(self, request: Request, call_next):
        try:
            return await asyncio.wait_for(
                call_next(request),
                timeout=self.timeout
            )
        except asyncio.TimeoutError:
            return JSONResponse(
                status_code=503,
                content={
                    "detail": "服務繁忙，請稍後再試",
                    "error": "Request timeout"
                }
            )
```

**實作方案 B：裝置狀態快取（推薦）**
```python
# backend/services/device_detector.py
class DeviceDetector:
    def __init__(self):
        self._device_cache = None
        self._cache_time = None
        self._cache_ttl = 300  # 5 分鐘快取
    
    def get_device_info_cached(self) -> dict:
        """取得裝置資訊（帶快取）"""
        now = time.time()
        if self._device_cache is None or \
           (now - self._cache_time) > self._cache_ttl:
            # 快取過期，重新偵測
            self._device_cache = self.get_device_info()
            self._cache_time = now
        return self._device_cache
```

**實作方案 C：Health Check 快速路徑**
```python
# backend/api/routes.py
@router.get("/health", response_model=HealthStatus)
async def health_check(quick: bool = False):
    """
    健康檢查端點（支援快速模式）
    
    - quick=true: 只返回快取資訊，不重新偵測裝置
    - quick=false: 完整健康檢查（預設）
    """
    if quick:
        # 快速模式：使用快取
        device_info = device_detector.get_device_info_cached()
    else:
        # 完整模式：重新偵測
        device_detector.detect_best_device()
        device_info = device_detector.get_device_info()
    
    # ... 其他邏輯
```

### 解決方案 2：統一版本號管理

**方案 A：創建 VERSION 檔案（推薦）**
```python
# backend/core/version.py
import os

def get_version() -> str:
    """從 VERSION 檔案讀取版本號"""
    version_file = os.path.join(
        os.path.dirname(__file__), '..', '..', 'VERSION'
    )
    try:
        with open(version_file, 'r') as f:
            return f.read().strip()
    except Exception:
        return "0.0.0"  # 預設版本

__version__ = get_version()
```

```text

```

**方案 B：從 Git Tag 自動生成（進階）**
```python
# backend/core/version.py
import subprocess

def get_version_from_git() -> str:
    """從 Git tag 取得版本號"""
    try:
        version = subprocess.check_output(
            ['git', 'describe', '--tags', '--always'],
            stderr=subprocess.DEVNULL
        ).decode().strip()
        return version
    except Exception:
        return "3.5.4"  # Fallback

__version__ = get_version_from_git()
```

**何時需要重啟**：
| 變更類型 | 是否需要重啟 | 原因 |

| Python 程式碼（.py） | ❌ 否 | `--reload` 自動重載 |
