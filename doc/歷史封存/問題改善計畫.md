## 🔍 問題一：VAD 參數 API 不相容

### 第一性原理分析

```
錯誤訊息：VadOptions.__init__() got an unexpected keyword argument 'threshold'
                    ↓ 為什麼？
faster-whisper 1.1.0 的 VadOptions 使用不同的參數名稱
                    ↓ 為什麼？
PyPI 發布的 1.1.0 版本與 GitHub master 分支的 API 不同
                    ↓ 為什麼？
faster-whisper 在 master 分支更新了 VAD 參數名稱，但尚未發布新版本
                    ↓ 根本原因
版本 1.1.0 (PyPI) 使用: onset, offset
版本 master (GitHub) 使用: threshold, neg_threshold
```

### 問題詳情

| 項目 | faster-whisper 1.1.0 (PyPI) | faster-whisper master (GitHub) |
|------|----------------------------|-------------------------------|
| 語音偵測閾值 | `onset` | `threshold` |
| 靜音偵測閾值 | `offset` | `neg_threshold` |
| 預設值 onset/threshold | 0.5 | 0.5 |
| 預設值 offset/neg_threshold | 0.35 | None (自動計算) |

### 解決方案

**方案 A：適配現有版本（推薦）**

修改 `transcription.py` 中的 VAD 參數名稱，適配 faster-whisper 1.1.0：

```python
# 修改前（錯誤）
vad_params = {
    "threshold": settings.ASR_VAD_THRESHOLD,
    "min_speech_duration_ms": settings.ASR_VAD_MIN_SPEECH_MS,
    "min_silence_duration_ms": settings.ASR_VAD_MIN_SILENCE_MS,
    "speech_pad_ms": settings.ASR_VAD_SPEECH_PAD_MS
}

# 修改後（正確）
vad_params = {
    "onset": settings.ASR_VAD_THRESHOLD,        # 語音偵測閾值
    "offset": settings.ASR_VAD_THRESHOLD - 0.15, # 靜音偵測閾值
    "min_speech_duration_ms": settings.ASR_VAD_MIN_SPEECH_MS,
    "min_silence_duration_ms": settings.ASR_VAD_MIN_SILENCE_MS,
    "speech_pad_ms": settings.ASR_VAD_SPEECH_PAD_MS
}
```

**方案 B：升級至 GitHub master 版本**

```bash
pip install git+https://github.com/SYSTRAN/faster-whisper.git
```

**CTO 建議**：採用方案 A，避免使用未發布版本帶來的穩定性風險。

### 相關檔案修改

| 檔案 | 修改內容 |
|------|----------|
| `backend/services/transcription.py` | 修改 vad_params 參數名稱 |
| `backend/core/config.py` | 確認設定參數名稱一致 |
| `config.yaml` | 確認參數名稱一致 |

## 🔍 問題二：日誌管理機制不完善

### 第一性原理分析

```
問題表現：debug 困難，無法追蹤系統問題
                    ↓ 為什麼？
日誌分散在多個位置，無法集中查看
                    ↓ 為什麼？
缺乏統一的日誌管理機制
                    ↓ 為什麼？
專案初期未規劃完善的可觀測性架構
                    ↓ 根本原因
缺乏生產級日誌管理策略
```

### 現有問題

| 問題 | 影響 |
|------|------|
| 日誌僅輸出到 stdout | 容器重啟後日誌丟失 |
| 缺乏結構化日誌 | 難以程式化分析 |
| 無日誌輪轉 | 磁碟空間可能耗盡 |
| 無日誌級別管理 | 開發/生產環境難以區分 |
| 無請求追蹤 ID | 難以追蹤單一請求的完整流程 |

### 解決方案：完善日誌管理模組

#### 1. 日誌架構設計

```
┌─────────────────────────────────────────────────────────┐
│                    Application                           │
├─────────────────────────────────────────────────────────┤
│                  LogManager (新增)                       │
│  ┌─────────────┬─────────────┬─────────────────────┐    │
│  │ Console     │ File        │ JSON Structured     │    │
│  │ Handler     │ Handler     │ Handler             │    │
│  └─────────────┴─────────────┴─────────────────────┘    │
├─────────────────────────────────────────────────────────┤
│               Log Storage                               │
│  ┌─────────────┬─────────────┬─────────────────────┐    │
│  │ app.log     │ error.log   │ access.log          │    │
│  │ (all logs)  │ (errors)    │ (HTTP requests)     │    │
│  └─────────────┴─────────────┴─────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

#### 2. 新增功能

| 功能 | 說明 |
|------|------|
| **日誌分級** | DEBUG, INFO, WARNING, ERROR, CRITICAL |
| **日誌輪轉** | 每日輪轉，保留 30 天 |
| **結構化日誌** | JSON 格式，便於 ELK 分析 |
| **請求追蹤** | 每個請求分配唯一 trace_id |
| **性能監控** | 記錄每個操作的執行時間 |
| **錯誤上下文** | 自動記錄堆疊追蹤 |

#### 3. 新增檔案

| 檔案 | 說明 |
|------|------|
| `backend/core/log_manager.py` | 日誌管理核心模組 |

#### 4. 程式碼設計

```python
# backend/core/log_manager.py
from loguru import logger
import sys
from pathlib import Path

class LogManager:
    """
    政府智慧會議紀錄生成系統 日誌管理器
    
    功能：
    - 多目標輸出（Console + File + JSON）
    - 日誌輪轉（每日，保留 30 天）
    - 結構化日誌（JSON 格式）
    - 請求追蹤（trace_id）
    """
    
    def __init__(self, log_dir: str = "data/logs", level: str = "INFO"):
        self.log_dir = Path(log_dir)
        self.log_dir.mkdir(parents=True, exist_ok=True)
        self.level = level
        
    def setup(self):
        # 移除預設 handler
        logger.remove()
        
        # Console 輸出（彩色，適合開發）
        logger.add(
            sys.stdout,
            level=self.level,
            format="<green>{time:YYYY-MM-DD HH:mm:ss}</green> | "
                   "<level>{level: <8}</level> | "
                   "<cyan>{name}</cyan>:<cyan>{function}</cyan>:<cyan>{line}</cyan> | "
                   "<level>{message}</level>",
            colorize=True
        )
        
        # 應用日誌（所有級別）
        logger.add(
            self.log_dir / "app_{time:YYYY-MM-DD}.log",
            rotation="00:00",  # 每日輪轉
            retention="30 days",
            level="DEBUG",
            format="{time:YYYY-MM-DD HH:mm:ss.SSS} | {level: <8} | {name}:{function}:{line} | {message}",
            encoding="utf-8"
        )
        
        # 錯誤日誌（僅 ERROR 以上）
        logger.add(
            self.log_dir / "error_{time:YYYY-MM-DD}.log",
            rotation="00:00",
            retention="90 days",
            level="ERROR",
            format="{time:YYYY-MM-DD HH:mm:ss.SSS} | {level: <8} | {name}:{function}:{line} | {message}\n{exception}",
            encoding="utf-8",
            backtrace=True,
            diagnose=True
        )
        
        # JSON 結構化日誌（便於分析）
        logger.add(
            self.log_dir / "structured_{time:YYYY-MM-DD}.jsonl",
            rotation="00:00",
            retention="30 days",
            level="INFO",
            serialize=True,
            encoding="utf-8"
        )
        
        return logger
```

## ⚠️ 潛在盲點檢查

### 已識別風險

| 風險 | 影響 | 緩解措施 |
|------|------|----------|
| 日誌磁碟空間 | 長期運行可能耗盡磁碟 | 設定 30 天自動輪轉 |
| 日誌敏感資訊 | 可能記錄個人資料 | 不記錄音檔內容 |
| 性能影響 | 日誌寫入可能影響性能 | 使用非同步寫入 |
| faster-whisper 版本更新 | 未來版本可能再次變更 API | 建立版本相容性檢查 |

### 相容性檢查

```python
# 建議新增的版本相容性檢查
def get_vad_params(threshold: float, min_speech_ms: int, min_silence_ms: int, speech_pad_ms: int) -> dict:
    """根據 faster-whisper 版本返回正確的 VAD 參數"""
    import faster_whisper
    from packaging import version
    
    fw_version = version.parse(faster_whisper.__version__)
    
    # 假設未來 1.2.0 版本使用 threshold 參數
    if fw_version >= version.parse("1.2.0"):
        return {
            "threshold": threshold,
            "min_speech_duration_ms": min_speech_ms,
            "min_silence_duration_ms": min_silence_ms,
            "speech_pad_ms": speech_pad_ms
        }
    else:
        # 1.1.0 版本使用 onset/offset
        return {
            "onset": threshold,
            "offset": max(threshold - 0.15, 0.01),
            "min_speech_duration_ms": min_speech_ms,
            "min_silence_duration_ms": min_silence_ms,
            "speech_pad_ms": speech_pad_ms
        }
```
