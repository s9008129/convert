## 📋 修復摘要

本次修復解決了 `No module named 'av'` 持續性錯誤，該錯誤導致音訊轉錄功能完全失效。

### 問題根源（第一性原理分析）

經過深度分析，發現以下根本問題：

| # | 問題 | 風險等級 | 狀態 |
|---|------|----------|------|
| 1 | 多個啟動腳本使用不同 Python 環境 | 🔴 Critical | ✅ 已修復 |
| 2 | venv 指向錯誤的 Python (anaconda base) | 🔴 Critical | ✅ 已修復 |
| 3 | `scripts/start-mac-native.sh` 使用 venv | 🔴 Critical | ✅ 已修復 |
| 4 | 日誌系統不完善，無法追蹤問題 | 🟠 High | ✅ 已修復 |
| 5 | 缺乏環境驗證機制 | 🟡 Medium | ✅ 已修復 |

---

## 🛠️ 修復內容

### 1. 環境統一（Phase 1）

- ✅ 刪除混亂的 `venv/` 目錄（已備份至 `venv.backup.*`）
- ✅ 修改 `scripts/start-mac-native.sh` 使用 conda meetingscribe
- ✅ 修改 `scripts/restart-mac-native.sh` 使用 conda meetingscribe
- ✅ 更新 `start_service.sh` 加入環境驗證

### 2. 環境驗證腳本（Phase 1.3）

新增 `scripts/verify_env.py`，在服務啟動前自動檢查：
- Python 版本和執行環境
- FFmpeg 系統依賴
- 所有關鍵模組（av, faster-whisper, fastapi 等）
- 可選模組（mlx-whisper）
- 目錄結構和配置檔案

### 3. 日誌系統升級（Phase 2）

升級 `backend/core/logger.py` 至 v2.0：
- 控制台彩色輸出
- 檔案日誌（每日輪轉，保留 30 天）
- 錯誤日誌（獨立檔案，保留 90 天）
- JSON 結構化日誌（用於分析）
- 任務 ID 綁定功能

### 4. 測試腳本（Phase 3）

新增 `scripts/test_full_pipeline.py`，自動化驗證：
- 服務健康檢查
- 配置 API
- 檔案上傳
- 任務狀態查詢
- 任務完成
- 日誌系統
