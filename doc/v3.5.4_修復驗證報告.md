- **嚴重程度**：🔴 高（導致系統崩潰）
- **現象**：前端顯示「處理失敗」，錯誤訊息為 `[Errno 32] Broken pipe`
- **影響範圍**：所有使用 WebSocket 的任務處理流程

### 問題 2：排隊人數顯示不一致
- **嚴重程度**：🟡 中（影響用戶體驗）
- **現象**：頂部狀態欄顯示「排隊: 0」，但排隊區塊顯示「您的排隊位置: 1」
- **影響範圍**：前端排隊狀態顯示

## 🔍 根本原因分析（First Principles）

### 問題 1 根本原因

**物理層面**：
- WebSocket 是基於 TCP 的雙向通訊協議
- 當客戶端關閉連線時，TCP 連線被中斷
- 伺服器端若嘗試向已關閉的 socket 寫入資料，系統會回傳 SIGPIPE 信號

**程式層面**：
- Python 中 SIGPIPE 表現為 `BrokenPipeError` (Errno 32)
- FastAPI WebSocket 在連線中斷後，`send_json()` 會拋出異常
- 原程式碼未捕獲此類異常，導致整個請求處理函數崩潰

**時序問題**：
```
客戶端                     伺服器
   |                          |
   |---- WebSocket 連線 ----->|
   |                          |
   |<--- 初始狀態推送 --------|
   |                          |
   | [用戶關閉瀏覽器]         |
   X （連線中斷）             |
                              |
                              |--> 嘗試 send_json()
                              |--> BrokenPipeError ❌
                              |--> 未處理，拋出異常
```

### 問題 2 根本原因

**狀態同步問題**：
- 後端：任務從隊列取出時，`_queue.popleft()` 立即執行，`total_queued` 減 1
- 前端：仍顯示任務的舊 `queue_position` 值
- 時序窗口：從任務取出到前端收到狀態更新之間存在延遲

**資料模型不一致**：
```python
# 後端邏輯
task = self._queue.popleft()  # total_queued 立即變為 0
task.queue_position = None    # 但任務物件的 queue_position 被設為 None
task.status = TaskStatus.PENDING

# 前端邏輯
if (status === 'queued') {
    // 此時 status 可能已經是 'pending'，但前端仍可能顯示舊資料
    updateQueueDisplay(queue_position, total_queued, message);
}
```

## ✅ 修復方案（基於第一原理）

### 修復 1：WebSocket 錯誤處理

**設計原則**：
1. **優雅降級**：連線失敗不應影響整體服務
2. **資源清理**：失效連線應立即清除，避免記憶體洩漏
3. **可觀測性**：記錄詳細日誌，協助診斷問題

**實作細節**：

```python
# backend/api/websocket.py - ConnectionManager.send_progress()
async def send_progress(self, task_id: str, message: ProgressMessage):
    if task_id not in self._connections:
        return
    
    dead_connections = set()
    
    for websocket in self._connections[task_id]:
        try:
            await websocket.send_json(message.model_dump())
        except (WebSocketDisconnect, RuntimeError, ConnectionResetError, BrokenPipeError) as e:
            # 明確捕獲所有可能的連線中斷異常
            log.debug(f"WebSocket 發送失敗 ({type(e).__name__}): {task_id}")
            dead_connections.add(websocket)
        except Exception as e:
            # 防禦性程式設計：捕獲其他未預期錯誤
            log.warning(f"WebSocket 發送時發生未預期錯誤: {e}")
            dead_connections.add(websocket)
    
    # 批次清理失效連線，避免迭代中修改集合
    for websocket in dead_connections:
        self.disconnect(websocket, task_id)
```

**錯誤類型處理**：
| 異常類型 | 原因 | 處理方式 |
|---------|------|---------|
| `BrokenPipeError` | TCP 連線已關閉（Errno 32） | 清理連線，記錄日誌 |
| `ConnectionResetError` | 連線被重置（Errno 54） | 清理連線，記錄日誌 |
| `RuntimeError` | WebSocket 狀態異常 | 清理連線，記錄日誌 |
| `WebSocketDisconnect` | FastAPI 自動偵測斷線 | 清理連線，記錄日誌 |

### 修復 2：排隊顯示同步

**設計原則**：
1. **狀態驅動 UI**：UI 顯示應完全由後端狀態驅動
2. **及時隱藏**：不再排隊的任務應立即隱藏排隊區塊
3. **資料一致性**：前端顯示資料應與後端狀態同步

**實作細節**：

```javascript
// frontend/js/app.js - handleProgressUpdate()
function handleProgressUpdate(message) {
    const progress = message.progress || 0;
    const status = message.status;
    
    // 嚴格檢查：只有真正排隊時才顯示排隊區塊
    if (status === 'queued' && message.queue_position) {
        const totalQueued = message.queue_total || 0;
        updateQueueDisplay(message.queue_position, totalQueued, message.message);
        return;
    }
    
    // 任務不在排隊中，立即隱藏排隊區塊
    if (elements.queueSection && status !== 'queued') {
        elements.queueSection.style.display = 'none';
    }
    
    // 後續處理進度條等...
}
```

```python
# backend/api/websocket.py - broadcast_queue_update()
async def broadcast_queue_update(self):
    queue_status = task_queue.get_queue_status()
    
    for task_id, connections in self._connections.items():
        task = task_queue.get_task(task_id)
        if task and task.status == TaskStatus.QUEUED:
            # 確保使用最新的排隊位置
            current_position = task_queue.get_task_position(task_id)
            message = ProgressMessage(
                task_id=task_id,
                status=task.status,
                progress=task.progress,
                stage=task.stage,
                message="排隊中",
                queue_position=current_position or task.queue_position,
                queue_total=queue_status.total_queued
            )
            await self.send_progress(task_id, message)
```
